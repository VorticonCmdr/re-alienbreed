# .256 — raw indexed VGA bitmap

[Format index](README.md) · Researched and inspected 2026-10-03

**Evidence status:** Verified bitmap layout.

## Identification and purpose

All 18 files under `LBMS/` are 64,768 bytes. They have no signature, dimensions, or IFF chunk headers. Their payload is a 320 × 200 indexed bitmap followed by a 256-color palette. These are graphics sheets; interpreting `TAA.256` in this layout produced a recognizable tile gallery during visual inspection.

The `LBMS` directory name does not make these files standard `.LBM`/IFF images. A tile gallery is stored as a continuous image, rather than as sequential 256-byte tile records.

## Verified layout

| Offset | Length | Content |
| --- | ---: | --- |
| `0x0000` | 64,000 | One unsigned palette index per pixel, rows from top to bottom |
| `0xFA00` | 768 | 256 RGB triples, each component in the range 0–63 |

Pixel `(x, y)` is byte `y * 320 + x`. Palette entry `i` starts at `64000 + 3*i`. All files have a 768-byte tail with no component above 63. An 8-bit display conversion can use `round(component * 255 / 63)`.

The row-major addressing and RGB palette interpretation agree with the [VGA programming reference](https://delorie.com/djgpp/doc/brennan/brennan_access_vga.html); the offsets and fixed lengths above were measured from this collection.

## Reading and remaining questions

Require exactly 64,768 bytes for this observed variant. Keep palette indices when exporting, and save a separate copy if converting to PNG. Decode a [`.VHF`](vhf.md) first to obtain the same basic layout.

The game's tile-number-to-sheet-coordinate mapping and the meaning of the `A`, `B`, and `AN` filename variants were not verified. Do not assume 250 complete 16 × 16 tiles: the 200-pixel image height is not a multiple of 16.
